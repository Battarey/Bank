# check

Модуль антифрод-проверки транзакций — оркестрация AML-правил.

## Файлы

| Файл         | Назначение                                                              |
|--------------|-------------------------------------------------------------------------|
| `router.py`  | FastAPI-эндпоинт `POST /check`, схемы запроса и ответа                  |
| `service.py` | `check_transaction()` — прогон pending-операции по всем AML-правилам    |

## Логика `check_transaction()`

1. Принимает параметры операции: `account_id`, `tx_type`, `amount`, `currency`
2. Последовательно вызывает все правила из `ALL_RULES` (см. `rules.py`)
3. Каждое срабатывание сохраняется как событие в MongoDB через `store.save_event()`
4. Возвращает список `Violation` (пустой — операция разрешена)

## Эндпоинт

| Метод | Путь     | Описание                                       |
|-------|----------|------------------------------------------------|
| POST  | `/check` | Проверить pending-транзакцию по AML-правилам   |

### Запрос (`SecurityCheckRequest`)

| Поле         | Тип       | Описание                                    |
|--------------|-----------|---------------------------------------------|
| `account_id` | `UUID`    | UUID счёта                                  |
| `tx_type`    | `str`     | Тип операции: deposit, withdrawal, transfer |
| `amount`     | `Decimal` | Сумма (> 0, до 18 цифр, 2 знака после)      |
| `currency`   | `str`     | Валюта счёта                                |

### Ответ (`SecurityCheckResponse`)

| Поле         | Тип                | Описание                                             |
|--------------|--------------------|------------------------------------------------------|
| `allowed`    | `bool`             | `true` — операция разрешена, `false` — заблокирована |
| `violations` | `list[ViolationItem]` | Список сработавших правил (пустой если `allowed`) |
