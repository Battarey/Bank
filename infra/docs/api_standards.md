# API & Архитектурные стандарты

Данный документ описывает фундаментальные правила и стандарты, принятые в банковском приложении.

## 1. Стандарт банковского счета (20 знаков)

Каждый открываемый счет имеет уникальный 20-значный номер, генерируемый по формату:

```
TTTTTCCCКBBBBNNNNNNN
│     │  │ │    └── индивидуальный номер (7 цифр, случайный)
│     │  │ └─────── код отделения (4 цифры: 0001)
│     │  └───────── контрольная цифра (1 цифра)
│     └──────────── код валюты (3 цифры)
└────────────────── код балансового счёта (5 цифр)
```

### Справочник кодов:
- **Балансовые счета (Типы):** 
  - `40817` — Расчетный (checking)
  - `42301` — Накопительный (savings)
  - `45505` — Кредитный (credit)
  - `42305` — Вклад (deposit)
- **Валюты:**
  - `810` — RUB
  - `840` — USD
  - `978` — EUR

## 2. Политики безопасности (Security & AML)

Система автоматически применяет наборы правил для защиты средств клиентов.

### Правила Антифрода (AML)
Любая исходящая транзакция проверяется сервисом `security_service`. Пороги настраиваются через переменные окружения:

| Правило              | Описание                           | Порог по умолчанию  |
|:---------------------|:-----------------------------------|:--------------------|
| `large_single_tx`    | Крупная разовая операция           | 600 000 RUB         |
| `daily_amount_limit` | Суммарный объём за 24 ч            | 1 000 000 RUB       |
| `daily_tx_count`     | Количество операций за 24 ч        | 20                  |
| `rapid_fire`         | 5+ операций за 3 минуты            | 5 / 3 мин           |
| `structuring`        | Дробление крупных сумм (3+ мелких) | 0.9 от порога       |
| `round_amount`       | Серия крупных круглых переводов    | ≥ 100k, кратно 10k  |

### Политика блокировки PIN-кода
Защита от перебора PIN-кода (Brute-force) реализована в `auth_service`:
1. **1–4 ошибки**: Предупреждение о количестве попыток.
2. **5 ошибок**: Кулдаун **5 минут** (429 Too Many Requests).
3. **10 ошибок**: Повторный кулдаун **5 минут**.
4. **15 ошибок**: Полная **блокировка аккаунта** (status → `blocked`) + каскадная заморозка всех счетов.

## 3. Технические паттерны

### Предотвращение Deadlock-ов
При переводах между счетами всегда происходит блокировка двух строк в БД. Чтобы избежать взаимной блокировки (Deadlock), сервисы всегда сортируют UUID счетов и блокируют их в порядке возрастания:
`lock_order = sorted([account_from_id, account_to_id])`
