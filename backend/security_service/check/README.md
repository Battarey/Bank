# Модуль проверок (check)

Движок правил (Rules Engine), выполняющий анализ транзакций на лету.

## Файлы
- `router.py`: Эндпоинт `POST /check`.
- `service.py`: Логика оркестрации правил.
- `rules.py`: Реализация конкретных алгоритмов проверки (AML).

## Эндпоинт `/check`
Принимает детали операции (сумма, валюта, ID счета) и возвращает объект `SecurityCheckResponse`.

### Логика обработки
1.  **Инициализация**: Загрузка контекста пользователя и истории его операций за последнее время.
2.  **Прогон по правилам**: Последовательное выполнение всех активных проверок.
3.  **Агрегация**: Если хотя бы одно правило возвращает `Violation`, транзакция помечается как `allowed: false`.
4.  **Запись**: Факт нарушения и детали сработавшего правила отправляются в модуль `store` для сохранения.

## Набор правил (AML Rules)
- **LimitExceeded**: Превышение максимально допустимой суммы разовой операции.
- **VelocityCheck**: Слишком много операций за короткий промежуток времени.
- **AccountStatus**: Проверка, не находится ли счет в статусе подозрительного или ограниченного.
