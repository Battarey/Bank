Специализированный микросервис для обеспечения безопасности финансовых операций (AML/CFT). Выполняет реалтайм-валидацию транзакций по набору правил и ведет архив инцидентов.

## Архитектура

Сервис следует стандартной 4-х слойной архитектуре с расширенным репозиторным слоем для поддержки MongoDB.

```text
security_service/
├── api/                # Эндпоинты оценки транзакций
├── services/           # Ядро антифрода: правила оценки и оркестрация
├── repositories/       # Работа с Postgres (чтение лимитов) и MongoDB (аудит)
├── core/               # Инфраструктура: uow, config, exceptions
├── main.py             # Точка входа
└── README.md
```

## Как это работает

1.  **Запрос**: `Transaction Service` вызывает роут `/security/evaluations` перед завершением любой финансовой проводки.
2.  **Валидация**: Сервис последовательно применяет набор правил (Rules Engine):
    -   **Large Transaction**: Проверка на превышение разового лимита.
    -   **Daily Volume**: Контроль суммарного оборота по счёту за 24 часа.
    -   **Frequency**: Защита от Rapid Fire (слишком частые мелкие платежи).
    -   **Structuring**: Выявление попыток дробления крупных сумм.
3.  **Результат**: Возвращается вердикт `allowed: true/false`. При `false` в ответе передается детальный список нарушений.
4.  **Реакция**: Информация о нарушениях сохраняется в MongoDB и отправляется в системный аудит через RabbitMQ.

## API Спецификация

Все внутренние запросы требуют заголовок `X-Internal-Key`.

| Метод | Путь                    | Описание                                  | Заголовки                  |
|-------|-------------------------|-------------------------------------------|----------------------------|
| POST  | `/security/evaluations` | Провести AML-проверку транзакции          | `X-Internal-Key`           |
| GET   | `/health`               | Проверка состояния сервиса (Mongo, RMQ)   | -                          |

## Доменные события (Domain Events)

| Событие         | Получатель (Exchange) | Описание                                   |
|-----------------|-----------------------|--------------------------------------------|
| `aml_violation` | `logs`                | Регистрация подозрительной активности      |

## Переменные окружения

| Ключ | Описание | Значение по умолчанию |
|------|----------|-----------------------|
| `APP_ENV` | Окружение (local, test, dev, prod) | `local` |
| `DATABASE_URL` | URL для чтения истории (PostgreSQL) | `postgresql+asyncpg://...` |
| `MONGO_URL` | Хранилище инцидентов безопасности | `mongodb://mongodb:27017/bank_security_db` |
| `RABBITMQ_URL` | URL брокера для публикации алертов | `amqp://guest:guest@localhost:5672/` |
| `INTERNAL_API_KEY` | Секретный ключ для авторизации Gateway | - |

## Технологии
- **FastAPI**: Высокопроизводительное API.
- **MongoDB**: Эффективное хранение неструктурированных журналов инцидентов.
- **SQLAlchemy**: Чтение данных о балансах и предыдущих операциях из Core DB.
- **Rules Engine**: Масштабируемая система правил AML.
