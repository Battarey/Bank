# Account Service

Микросервис управления жизненным циклом банковских счетов: открытие, мониторинг состояния, блокировка (заморозка) и закрытие.

## Файловая архитектура
```
account_service/
├── open_account/         # Создание счетов, листинг и детализация (Service + Router)
├── close_account/        # Логика мягкого удаления (статус 'closed')
├── freeze_account/       # Заморозка операций (статус 'frozen')
├── queries/              # CQRS: Высокопроизводительный Query Layer (Raw SQL)
├── exceptions.py         # Бизнес-исключения (AccountLimitReached, AccountNotFound и др.)
├── repository.py         # SQLAlchemy Репозиторий для записи (BankAccountRepository)
├── uow.py                # Unit of Work (AccountUnitOfWork)
├── main.py               # Точка входа FastAPI
└── README.md
```

## Бизнес-логика

### 1. Генерация номера счёта
Каждый счёт получает уникальный 20-значный номер формата: `[Тип:5][Валюта:3][Бранч:4][Рандом:8]`.
- **Типы**: Расчётный (40817), Накопительный (42301), Кредитный (45505), Вклад (42305).
- **Валюты**: RUB (810), USD (840), EUR (978).
- **Бранч**: По умолчанию `0001`.

### 2. Лимиты и ограничения
- **Максимум 3 открытых счёта** одного типа в одной валюте для одного пользователя.
- **Закрытие счёта**: Возможно только при нулевом балансе и если счёт не заморожен. Статус меняется на `closed`, физического удаления из БД не происходит.
- **Заморозка (Freeze)**: Блокирует любые расходные операции по счёту.
- **Разморозка (Unfreeze)**: Пользователь не может самостоятельно разморозить счёт, если он был заморожен системой безопасности (`frozen_by='system'`).

## API v1 (Внутренний)

Все запросы требуют заголовок `X-Internal-Key` для авторизации между сервисами.

| Метод  | Путь                         | Описание                                  | Заголовки                  |
|--------|------------------------------|-------------------------------------------|----------------------------|
| POST   | `/accounts`                  | Открыть новый счёт (`type`, `currency`)   | `X-User-ID`                |
| GET    | `/accounts`                  | Список всех счетов пользователя (CQRS)    | `X-User-ID`                |
| GET    | `/accounts/{id}`             | Детальная информация о счёте (CQRS)       | `X-User-ID`                |
| DELETE | `/accounts/{id}`             | Закрыть счёт (условие: баланс = 0)        | `X-User-ID`                |
| POST   | `/accounts/{id}/suspensions` | Заморозить счёт                           | `X-User-ID`                |
| DELETE | `/accounts/{id}/suspensions` | Разморозить счёт (только `frozen_by=user`)| `X-User-ID`                |
| GET    | `/health`                    | Проверка состояния сервиса                | -                          |

## Доменные события (Domain Events)

События регистрируются в `uow.events` и автоматически публикуются в RabbitMQ после `uow.commit()`.

| Событие            | Routing Key         | Описание                                   |
|--------------------|---------------------|--------------------------------------------|
| `account_opened`   | `email.send`        | Уведомление об открытии счёта              |
| `account_closed`   | `email.send`        | Уведомление о закрытии счёта               |
| `account_frozen`   | `email.send`        | Уведомление о блокировке                   |
| `account_unfrozen` | `email.send`        | Уведомление о восстановлении доступа       |
| `open_account`     | `log.account`       | Запись в аудит-лог (создание)              |
| `freeze_account`   | `log.account`       | Запись в аудит-лог (заморозка)             |

## Технологии
- **FastAPI**: Фреймворк API.
- **SQLAlchemy 2.0**: Работа с PostgreSQL.
- **Aio-pika**: Асинхронная работа с RabbitMQ.
- **CQRS**: Раздельное использование `repository.py` (запись) и `queries/` (чтение).
