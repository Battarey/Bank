Микросервис управления жизненным циклом банковских счетов: открытие, мониторинг состояния, блокировка (заморозка) и закрытие.

## Архитектура

Сервис построен по четырехслойной архитектуре для обеспечения чистоты кода и разделения ответственности:

```text
account_service/
├── api/             # Слой API: роутеры и обработка HTTP-запросов
├── services/        # Слой бизнес-логики: реализация сценариев использования
├── repositories/    # Слой доступа к данным: работа с БД (Команды и Запросы)
├── core/            # Ядро: конфигурация, исключения, Unit of Work
├── main.py          # Точка входа в приложение
└── README.md        # Общая документация
```

## Бизнес-логика

### 1. Генерация номера счёта
Каждый счёт получает уникальный 20-значный номер формата: `[Тип:5][Валюта:3][Бранч:4][Рандом:8]`.
-   **Типы**: Расчётный (40817), Накопительный (42301), Кредитный (45505), Вклад (42305).
-   **Валюты**: RUB (810), USD (840), EUR (978).
-   **Бранч**: По умолчанию 0001.

### 2. Лимиты и ограничения
-   **Максимум 3 открытых счёта** одного типа в одной валюте для одного пользователя.
-   **Закрытие счёта**: Возможно только при нулевом балансе и если счёт не заморожен. Статус меняется на `closed`, физического удаления из БД не происходит.
-   **Заморозка (Freeze)**: Блокирует любые расходные операции по счёту.
-   **Разморозка (Unfreeze)**: Пользователь не может самостоятельно разморозить счёт, если он был заморожен системой безопасности (`frozen_by='system'`).

## API Спецификация

Все внутренние запросы требуют заголовок `X-Internal-Key`.

| Метод  | Путь                         | Описание                                  | Заголовки                  |
|--------|------------------------------|-------------------------------------------|----------------------------|
| POST   | `/accounts`                  | Открыть новый счёт                        | `X-User-ID`                |
| GET    | `/accounts`                  | Список всех счетов пользователя           | `X-User-ID`                |
| GET    | `/accounts/{id}`             | Детальная информация о счёте              | `X-User-ID`                |
| DELETE | `/accounts/{id}`             | Закрыть счёт (условие: баланс = 0)        | `X-User-ID`                |
| POST   | `/accounts/{id}/suspensions` | Заморозить счёт                           | `X-User-ID`                |
| DELETE | `/accounts/{id}/suspensions` | Разморозить счёт (только `frozen_by=user`)| `X-User-ID`                |
| GET    | `/health`                    | Проверка состояния сервиса                | -                          |

## Доменные события (Domain Events)

События автоматически публикуются в RabbitMQ после успешного завершения транзакции (UoW).

| Событие            | Получатель (Exchange) | Описание                                   |
|--------------------|-----------------------|--------------------------------------------|
| `account_opened`   | `notifications`       | Уведомление об открытии счёта              |
| `account_closed`   | `notifications`       | Уведомление о закрытии счёта               |
| `account_frozen`   | `notifications`       | Уведомление о блокировке                   |
| `account_unfrozen` | `notifications`       | Уведомление о восстановлении доступа       |
| `open_account`     | `logs`                | Запись в аудит-лог (создание)              |
| `close_account`    | `logs`                | Запись в аудит-лог (закрытие)              |
| `freeze_account`   | `logs`                | Запись в аудит-лог (заморозка)             |
| `unfreeze_account` | `logs`                | Запись в аудит-лог (разморозка)            |

## Переменные окружения

| Ключ | Описание | Значение по умолчанию |
|------|----------|-----------------------|
| `APP_ENV` | Окружение (local, test, dev, prod) | `local` |
| `DATABASE_URL` | URL подключения к PostgreSQL | `postgresql+asyncpg://...` |
| `RABBITMQ_URL` | URL подключения к RabbitMQ | `amqp://guest:guest@localhost:5672/` |
| `INTERNAL_API_KEY` | Секретный ключ для межсервисных вызовов | - |

## Технологии
- **FastAPI**: Фреймворк для асинхронного API.
- **SQLAlchemy 2.0+**: ORM для работы с PostgreSQL (Async).
- **Aio-pika**: Асинхронный клиент для RabbitMQ.
- **Pydantic v2**: Валидация данных и схемы.
- **Unit of Work**: Паттерн управления транзакциями и событиями.
- **CQRS**: Разделение ответственности между репозиториями записи и чтения.
