# Хранилище событий (events)

Централизованное описание структур данных для асинхронного взаимодействия микросервисов (EDA).

## Иерархия классов

Все сообщения в системе наследуются от базового класса **`BaseEvent`** (на базе Pydantic), что гарантирует строгую типизацию и валидацию при обмене через RabbitMQ.

### 1. NotificationEvent
Используется для инициирования отправки уведомлений пользователю. Потребляется сервисом `notification_service`.
- **`type`**: Имя шаблона письма (welcome, login_alert и т.д.).
- **`to`**: Email получателя.
- **`variables`**: Словарь данных для подстановки в шаблон.

### 2. LogEvent
Используется для регистрации системных событий и аудита действий. Потребляется сервисом `log_service`.
- **`user_id`**: Идентификатор пользователя (если применимо).
- **`action`**: Описание совершенного действия.
- **`service`**: Имя микросервиса-источника.
- **`details`**: Дополнительная техническая информация.

## Принципы использования
События регистрируются в **Unit of Work** в процессе выполнения бизнес-логики и автоматически публикуются в соответствующий Exchange брокера сообщений после успешного коммита транзакции в базе данных.
