# Transaction Service

Ядро финансовых операций банковской платформы. Обеспечивает пополнение, снятие, переводы между счетами и ведение детальной истории транзакций с поддержкой высокой нагрузки и согласованности.

## Файловая архитектура
```
transaction_service/
├── transactions/         # Унифицированный роутер
├── deposit/              # Модуль пополнения
├── withdrawal/           # Модуль снятия
├── transfer/             # Модуль переводов
├── history/              # Модуль истории (CQRS)
├── repository.py         # Репозиторий транзакций
├── uow.py                # TransactionUnitOfWork
├── main.py               # Точка входа
└── README.md
```

## Архитектура и Структура
Сервис реализует **CQRS** и **Unit of Work**:
-   **`transactions/`**: Унифицированный роутер для создания операций.
-   **`deposit/`**, **`withdrawal/`**, **`transfer/`**: Бизнес-логика, выделенная в отдельные под-модули.
-   **`history/`**: Слой чтения (CQRS Query Layer), использующий сырой SQL для эффективной пагинации и фильтрации истории.
-   **`uow.py`**: Реализация `TransactionUnitOfWork` для атомарности переводов и пополнений.
-   **`repository.py`**: Управление сущностями транзакций и балансов.

## 🛰 API Эндпоинты

Все запросы требуют заголовки `X-Internal-Key` и `X-User-ID`.

| Метод  | Путь                         | Описание                                    |
|--------|------------------------------|-------------------------------------------|
| POST   | `/transactions`              | Создать транзакцию (тип: deposit/withdraw/transfer) |
| GET    | `/accounts/{id}/transactions`| История транзакций (пагинация, фильтры)   |

### Формат запроса `POST /transactions`
```json
{
  "type": "transfer",
  "from_account_id": "uuid",
  "to_account_id": "uuid",
  "amount": "100.50",
  "description": "Оплата услуг",
  "idempotency_key": "unique-request-id"
}
```

## ⚡ Ключевые Возможности

-   **Идемпотентность**: Поддержка `idempotency_key` гарантирует, что повторный запрос (напр. при сбое сети) не приведет к повторному списанию средств.
-   **Row-Level Locking**: Использование блокировок `FOR UPDATE` на уровне БД для предотвращения состояний гонки (Race Conditions) при параллельных транзакциях.
-   **Предотвращение Deadlocks**: Алгоритм упорядоченной блокировки UUID при межбанковских переводах.
-   **Безопасность (AML)**: Интеграция с `security_service` — каждая транзакция проходит автоматическую оценку рисков перед выполнением.
-   **Автоконвертация**: Поддержка переводов между счетами в разных валютах через интеграцию с `currency_service`.

## 📡 Доменные события (Domain Events)

-   **`TransactionCreated`**: Сведения о новой операции для аудит-лога.
-   **`NotificationEvent`**: Триггерит чеки и уведомления (`transaction_deposit`, `transaction_transfer` и др.).
-   **`BalanceChanged`**: Информация для аналитики и обновления балансов в кэше.

## 🛠 Технологии
-   **FastAPI**: API Framework.
-   **SQLAlchemy (Async)**: ORM для фиксации операций.
-   **Raw SQL / Query Layer**: Для высокоскоростной истории транзакций.
-   **PostgreSQL**: Источник истины для финансовых данных.
-   **RabbitMQ**: Доставка уведомлений о транзакциях.
