Централизованная система управления схемой реляционной базы данных PostgreSQL. Построена на базе **Alembic** и обеспечивает синхронизацию структуры данных между всеми микросервисами.

## Структура директории

```text
migrations/
├── alembic/              # Конфигурация и скрипты миграций
│   ├── versions/         # История изменений схемы (ревизии)
│   └── env.py            # Настройка окружения и импорт моделей
├── alembic.ini           # Глобальный конфигурационный файл Alembic
├── reset_and_upgrade.py  # Скрипт полной переинициализации базы (Dev-only)
└── README.md             # Инструкции по управлению схемой
```

## Рабочий процесс (Workflow)

Процесс изменения базы данных состоит из трех этапов:

### 1. Изменение моделей
Все изменения структуры таблиц должны начинаться с редактирования декларативных моделей в `backend/shared/models/`.

### 2. Генерация ревизии
После обновления моделей сгенерируйте файл миграции:
```powershell
alembic revision --autogenerate -m "краткое_описание_изменений"
```
*Внимательно проверьте созданный файл в `alembic/versions/` перед применением.*

### 3. Применение изменений
Обновите локальную или Docker-базу данных до последней версии:
```powershell
alembic upgrade head
```

## Управление версиями

| Задача | Команда |
|--------|---------|
| Просмотр текущей версии | `alembic current` |
| Просмотр истории | `alembic history --verbose` |
| Откат на 1 шаг назад | `alembic downgrade -1` |
| Полный апгрейд | `alembic upgrade head` |

## Безопасность и Правила

-   **Запрет ручных правок**: Никогда не меняйте структуру БД в Postgres вручную. Используйте только миграции.
-   **Atomic Changes**: Одна миграция должна содержать одно логическое изменение (например, добавление одной таблицы или индекса).
-   **Автоматизация**: В Docker-окружении контейнер `migrations` автоматически запускает `upgrade head` при старте системы, гарантируя актуальность схемы для всех сервисов.
