# Customer Service

Сервис управления данными клиентов, ответственный за жизненный цикл пользователя: от первичной регистрации (KYC) до обновления профиля и удаления аккаунта.

## Файловая архитектура
```
customer_service/
├── create_account/       # Пошаговый онбординг
├── update_user_data/     # Изменение профиля
├── delete_account/       # Закрытие профиля
├── queries/              # CQRS Профиль клиента
├── repository.py         # Репозиторий Customer
├── uow.py                # CustomerUnitOfWork
├── main.py               # Точка входа
└── README.md
```

## Архитектура и Структура
Сервис реализует **4-слойную архитектуру** с поддержкой **CQRS**:
-   **`create_account/`**: Логика пошагового онбординга (Черновики в Redis Stack).
-   **`update_user_data/`**: Модуль обновления персональных данных активных пользователей.
-   **`delete_account/`**: Процедура мягкого удаления (Soft Delete) с каскадными эффектами.
-   **`queries/`**: Оптимизированное чтение полного профиля пользователя (5+ таблиц) через Query Layer.
-   **`uow.py`**: Реализация `CustomerUnitOfWork`.

## 🛰 API Эндпоинты

| Метод  | Путь                               | Описание                                    |
|--------|------------------------------------|-------------------------------------------|
| POST   | `/onboarding`                      | Начать регистрацию (выдача Client ID)     |
| POST   | `/onboarding/{id}/personal-data`   | Шаг 1: ФИО, Дата рождения                 |
| POST   | `/onboarding/{id}/passport`        | Шаг 2: Серия, Номер, Кем выдан            |
| POST   | `/onboarding/{id}/identifiers`     | Шаг 3: ИНН, СНИЛС                         |
| POST   | `/onboarding/{id}/contacts`        | Шаг 4: Email, Телефон                     |
| POST   | `/onboarding/{id}/completion`      | Финализация (Перенос из черновиков в БД)  |
| GET    | `/users/me`                        | Получить полный профиль (CQRS)            |
| PUT    | `/users/me/personal-data`          | Обновить данные профиля                   |
| DELETE | `/users/me`                        | Удалить аккаунт (Soft Delete)             |

## 📋 Бизнес-логика

### Процесс Онбординга (KYC)
1.  Данные шагов сохраняются как JSON-черновики в **Redis Stack** с TTL 24 часа.
2.  На этапе `/completion` данные валидируются, сохраняются в PostgreSQL, создается пользователь в статусе `active`.
3.  Публикуется событие `WelcomeEmail`, инициирующее приветственное письмо.

### Удаление аккаунта
-   Выполняется **Soft Delete**: `status -> deleted`, `deleted_at -> now()`.
-   **Каскад**: Все открытые счета пользователя автоматически замораживаются (`frozen_by = system`), активные сессии аннулируются.

### CQRS Query Layer
Запрос `/users/me` использует агрегированный SQL-запрос для мгновенного получения данных из таблиц: `users`, `personal_data`, `passports`, `identifiers`, `contacts`.

## 📡 Доменные события (Domain Events)

-   **`CustomerCreated`**: Уведомление об успешной регистрации.
-   **`CustomerUpdated`**: Логирование изменений персональных данных.
-   **`CustomerDeleted`**: Инициация процесса закрытия доступа и отправки прощального письма.
