# Log Service

Микросервис централизованного сбора и хранения логов всей системы. Обеспечивает параллельную запись в аналитическое хранилище (ClickHouse) и аудит-лог пользователей (PostgreSQL).

## Архитектура
Проект следует стандартной 4-х слойной архитектуре с выделенным слоем для воркеров.

### Файловая структура
```text
log_service/
├── api/                # Слой API: Health-checks
├── services/           # Слой Services: Обработка и маршрутизация логов
├── repositories/       # Слой Repositories: ClickHouse и Postgres
├── workers/            # Слой Workers: RabbitMQ потребители
├── core/               # Слой Core: Config, Schemas
├── main.py             # Точка входа для API и Worker-ов
├── tests/              # Юнит-тесты
└── README.md
```

## Особенности
- **Параллельная запись**: Лог-событие одновременно сохраняется в ClickHouse (для Grafana/BI) и в `postgres_history` (для отображения в ЛК клиента).
- **TTL (Time To Live)**: Воркер автоматически очищает старые записи в `postgres_history` (по умолчанию 90 дней).
- **Graceful Shutdown**: Обработка сигналов завершения для корректного закрытия соединений и завершения обработки сообщений.

## Технологии
- **ClickHouse**: Аналитическое хранилище.
- **SQLAlchemy (PostgreSQL)**: Хранение действий пользователей.
- **RabbitMQ (aio-pika)**: Прием событий от других сервисов.
- **FastAPI**: Health-мониторинг зависимостей.
