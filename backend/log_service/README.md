# Log Service

Сервис централизованного сбора и хранения системных логов и аудита действий пользователей. Работает в режиме фонового потребителя (Consumer) событий из RabbitMQ.

## Файловая архитектура
```
log_service/
├── consumers.py      # Обработчик очереди RabbitMQ (aio-pika)
├── repository.py     # Логика записи в PostgreSQL и ClickHouse
├── service.py        # Бизнес-логика распределения логов
├── schemas.py        # Валидация входящих событий (LogEvent)
├── config.py         # Настройки подключений и TTL
├── main.py           # Точка входа (запуск воркера)
└── README.md
```

## Архитектура хранения

Сервис реализует стратегию двойной записи для разных типов задач:

### 1. PostgreSQL (postgres_history) — Аудит действий
Используется для хранения действий пользователей, которые должны быть доступны в интерфейсе (история операций, изменения настроек).
- **Модель**: `UserAction`.
- **Очистка (Retention)**: Реализована фоновая задача, которая раз в сутки удаляет записи старше **90 дней** для экономии места.

### 2. ClickHouse — Аналитика и мониторинг
Используется для хранения всех типов событий системы (включая технические логи и ошибки) без удаления.
- **Цель**: Глубокий анализ производительности, расследование инцидентов и построение Dashboards.
- **Оптимизация**: Прямая вставка через `shared.clickhouse_core`.

## Поток обработки данных
1. Микросервисы публикуют события в Exchange `logs.topic`.
2. `log_service` потребляет сообщения из очереди `log_queue`.
3. Сообщение валидируется через Pydantic схему `LogEvent`.
4. Сервис сохраняет данные в соответствующие репозитории асинхронно.

## Технологии
- **Python 3.12**: Основной язык.
- **Aio-pika**: Асинхронное взаимодействие с RabbitMQ.
- **SQLAlchemy 2.0**: Работа с Postgres History.
- **ClickHouse-driver**: Работа с аналитическим хранилищем.
