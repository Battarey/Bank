# Gateway Service (Go)

Центральный API Gateway системы, написанный на Go с использованием фреймворка Echo. Обеспечивает единую точку входа, проверку авторизации, управление сессиями и безопасное проксирование запросов к микросервисам.

## Файловая архитектура
```
gateway_service/
├── routes/          # Маршрутизация запросов к сервисам (Go-роуты)
├── middleware/      # AuthMiddleware, PIN-gate, CORS, Logging
├── proxy/           # Реверс-прокси: инъекция заголовков, Forwarding
├── redis/           # Клиент для работы с сессиями (Sessions Store)
├── config/          # Загрузка конфигурации из .env
├── docs/            # Автогенерируемая документация Swagger/OpenAPI
├── tests/           # Интеграционные и unit-тесты на Go
├── main.go          # Инициализация и запуск сервера Echo
└── README.md
```

## Ключевые функции
1.  **Централизованная авторизация**: Проверка `X-Session-Token` в Redis Middleware для всех защищенных запросов.
2.  **Безопасность (Internal Auth)**: Автоматическая инъекция `X-Internal-Key` во все запросы к внутренним сервисам, что предотвращает прямой доступ к микросервисам извне.
3.  **Управление сессиями**: Поддержка "скользящих сессий" (продление TTL при активности) и возможность мгновенного отзыва всех сессий пользователя.
4.  **Высокая производительность**: Использование неблокирующего I/O в Go и Echo для обработки сотен одновременных запросов с минимальными задержками.

## Почему Go?
Выбор Go для шлюза обусловлен:
- Низким потреблением памяти при большом количестве соединений.
- Скоростью работы со строками и заголовками.
- Нативной поддержкой конкурентности (Goroutines) для одновременного проксирования множества запросов.

## Технологии
- **Echo v4**: HTTP фреймворк.
- **Go-Redis**: Асинхронный клиент для Redis.
- **Reverse Proxy**: Прямое перенаправление трафика HTTP.
