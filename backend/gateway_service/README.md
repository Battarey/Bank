# Gateway Service (Go)

Центральный API Gateway системы, написанный на Go с использованием фреймворка Echo. Обеспечивает единую точку входа («Единое окно»), проверку авторизации, управление сессиями и безопасное проксирование запросов к микросервисам.

## Файловая архитектура
```
gateway_service/
├── routes/          # Обработчики запросов и Deep Healthcheck
├── middleware/      # Auth, Rate Limiting, Request ID, UUID Validation
├── proxy/           # Централизованная логика проксирования и Ping-тесты
├── redis/           # Клиенты для сессий и онбординга
├── schemas/         # Общие DTO для ответов (Success, Error, Health)
├── config/          # Загрузка конфигурации (Config via Environment)
├── docs/            # Автогенерируемая документация Swagger/OpenAPI
├── tests/           # Интеграционные и unit-тесты на Go
├── main.go          # Инициализация и запуск сервера Echo
└── README.md
```

## Ключевые функции

1.  **Централизованная авторизация**: Проверка `X-Session-Token` в Redis Middleware для всех защищенных путей (`/api/v1/...`).
2.  **Безопасность и Валидация**:
    *   **Rate Limiting**: Ограничение количества запросов (20 RPS на IP) для защиты от DoS-атак.
    *   **UUID Strict Validation**: Строгая проверка идентификаторов счетов во всех эндпоинтах для предотвращения атак типа Path Traversal.
    *   **Internal Auth**: Автоматическая инъекция `X-Internal-Key` во все внутренние запросы.
3.  **Обсервабельность (Observability)**:
    *   **X-Request-ID**: Сквозная трассировка запросов через все микросервисы для упрощения отладки в логах.
    *   **Deep Healthcheck**: Агрегированный мониторинг всей системы. Шлюз параллельно опрашивает все 9 микросервисов, которые, в свою очередь, проверяют свои БД (Postgres, ClickHouse, Mongo, Redis, RabbitMQ).
4.  **Управление сессиями**: Поддержка "скользящих сессий" в Redis и возможность мгновенного отзыва токенов.

## Технологии

- **Go 1.22+**
- **Echo v4**: Высокопроизводительный веб-фреймворк.
- **Go-Redis v9**: Пул соединений с Redis.
- **Swag**: Генерация OpenAPI спецификаций из комментариев к коду.

## Как запустить

Для генерации документации:
```bash
# В корне gateway_service
docker run --rm -v ${PWD}:/code ghcr.io/swaggo/swag:v1.16.4 init
```

Для сборки и запуска через Docker:
```bash
docker-compose up --build gateway_service
```

## Конфигурация
Все настройки передаются через переменные окружения (.env):
- `PORT`: Порт шлюза (по умолчанию 8080).
- `INTERNAL_API_KEY`: Секрет для авторизации между сервисами.
- `REDIS_SESSIONS_URL`: URL для хранилища сессий.
- `*_SERVICE_URL`: URL-адреса внутренних микросервисов.
