# HTTP Middleware (middleware)

Набор промежуточных слоев для обработки запросов, обеспечения безопасности и авторизации в API Gateway.

## Основные компоненты

### 1. AuthMiddleware (`auth.go`)
Центральный механизм безопасности, который:
- **Проверка сессии**: Извлекает `X-Session-Token` и проверяет его наличие в Redis.
- **Sliding Expiration**: Продлевает срок жизни токена (TTL) при каждом активном запросе (`TouchToken`).
- **Контекст**: Сохраняет `user_id` в контексте запроса Echo для дальнейшего использования в прокси.

### 2. PIN-gate (Логика авторизации)
Middleware реализует двухуровневую проверку доступа:
1.  **Публичные пути**: Запросы к `/auth/login-pin`, `/health`, `/docs` и шагам онбординга проходят без токена.
2.  **PIN-exempt**: Пути, доступные авторизованному пользователю без установленного PIN (например, `/auth/set-pin`, `/auth/logout`).
3.  **Защищенные пути**: Все остальные запросы (балансы, переводы) блокируются с ошибкой `403 Forbidden`, если в сессии отсутствует флаг `has_pin=true`.

## Логирование и CORS
Шлюз использует стандартные middleware Echo для логирования запросов и настройки политик CORS для фронтенд-приложений.
