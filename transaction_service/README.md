# Transaction Service

Микросервис финансовых операций: пополнение, снятие, переводы между счетами и история транзакций.

При каждой операции отправляет email-уведомления через RabbitMQ (шаблоны `transaction_deposit`, `transaction_withdrawal`, `transaction_transfer`, `transaction_incoming`) и публикует бизнес-события в exchange `logs` (routing key `log.transaction`) для аудит-лога и аналитики.

## Файловая архитектура
```
transaction_service/
├── deposit/              # Пополнение счёта
├── withdrawal/           # Снятие со счёта
├── transfer/             # Перевод между счетами (с автоконвертацией валют)
├── history/              # История операций с пагинацией
├── tests/
├── currency_client.py    # HTTP-клиент для Currency Service (курсы валют)
├── exceptions.py         # Единая иерархия исключений
├── main.py
├── Dockerfile
├── requirements.txt
└── README.md
```

## Эндпоинты

Все эндпоинты требуют заголовки `X-Internal-Key` и `X-User-ID`.

| Метод | Путь                                  | Код | Описание                          |
|-------|---------------------------------------|-----|-----------------------------------|
| POST  | `/accounts/{id}/deposit`              | 200 | Пополнить счёт                    |
| POST  | `/accounts/{id}/withdraw`             | 200 | Снять со счёта                    |
| POST  | `/accounts/{id}/transfer`             | 200 | Перевести на другой счёт          |
| GET   | `/accounts/{id}/transactions`         | 200 | История операций (пагинация)      |

## Бизнес-правила

### Пополнение (deposit)
- Счёт должен принадлежать пользователю и быть в статусе `open`
- Сумма > 0, до 2 знаков после запятой
- Блокировка строки `SELECT ... FOR UPDATE` на время операции
- Создаётся запись: `type=deposit`, `direction=incoming`, `status=posted`

### Снятие (withdrawal)
- Счёт должен принадлежать пользователю и быть в статусе `open`
- Проверка достаточности средств (`balance >= amount`)
- Блокировка строки `SELECT ... FOR UPDATE`
- Создаётся запись: `type=withdrawal`, `direction=outgoing`, `status=posted`

### Перевод (transfer)
- Счёт-отправитель должен принадлежать пользователю и быть в статусе `open`
- Счёт-получатель должен существовать и быть в статусе `open` или `frozen` (мягкая заморозка: входящие разрешены)
- **Кросс-валютные переводы:** если валюты счетов различаются, курс запрашивается из Currency Service (`GET /rates/{base}/{target}`), сумма зачисления конвертируется автоматически (округление `ROUND_HALF_UP`, 2 знака)
- При конвертации курс сохраняется в `external_ref` обеих транзакций (для аудита)
- AML-проверка через Security Service перед выполнением перевода (fail-open)
- Нельзя переводить самому себе (same account)
- Проверка достаточности средств
- **Deadlock prevention:** блокировка двух счетов в порядке `sorted([from_id, to_id])`
- Создаются **2 записи**: outgoing (у отправителя, `amount` в валюте отправителя) + incoming (у получателя, `amount` в валюте получателя)
- Уведомления: отправителю (`transaction_transfer`), получателю (`transaction_incoming`, если другой клиент) — при конвертации содержат информацию о курсе

### История (transactions)
- Пагинация: `limit` (1–100, по умолчанию 20), `offset` (≥ 0)
- Фильтры: `type` (deposit/withdrawal/transfer), `direction` (incoming/outgoing)
- Сортировка: `created_at DESC`
- Возвращает `total` — общее количество записей по фильтрам

## Обработка ошибок

| Код | Когда                                             |
|-----|---------------------------------------------------|
| 400 | Некорректные параметры запроса                    |
| 401 | Невалидный `X-Internal-Key`                       |
| 403 | Отсутствует `X-User-ID`                           |
| 404 | Счёт не найден / не принадлежит пользователю      |
| 409 | Счёт не открыт, совпадение счетов, конфликт       |
| 422 | Недостаточно средств                              |
| 502 | Не удалось получить курс валют (Currency Service) |
