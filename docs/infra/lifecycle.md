# Жизненный цикл и Эксплуатация (SRE)

Этот раздел описывает инженерные подходы к управлению ресурсами, качеству кода и развертыванию системы.

## 1. Управление ресурсами: BootstrapContainer

Система использует паттерн **Infrastructure Container** (реализован в `shared/bootstrap/container.py`) для централизованного управления всеми внешними зависимостями (БД, брокеры, кэш).

### Ключевые особенности:
-   **Ленивая инициализация (Lazy Init)**: Подключения к базам данных (Postgres, ClickHouse, Mongo) и RabbitMQ создаются только в момент первого обращения. Это ускоряет старт сервиса и экономит ресурсы.
-   **Единый источник истины**: Все настройки считываются через Pydantic Settings и валидируются при старте.
-   **Graceful Shutdown**: Контейнер предоставляет метод `dispose()`. При получении сигнала об остановке (SIGTERM), система корректно закрывает все пулы соединений, завершает текущие запросы и разрывает связь с брокером сообщений без потери данных.

## 2. Стандарты Docker: Multi-stage Builds

Все микросервисы используют двухэтапную сборку, что критически важно для безопасности и производительности в production.

1.  **Stage 1 (Builder)**: Устанавливаются инструменты сборки (компиляторы, заголовочные файлы). Собираются зависимости Python.
2.  **Stage 2 (Runtime)**: В финальный образ (на базе `python:slim` или `alpine`) копируются только готовые установленные пакеты и код.
-   **Результат**: Размер образа уменьшается в 2-3 раза, а отсутствие компиляторов в финальном образе снижает поверхность атаки.

## 3. Автоматизированный Аудит Качества

Для поддержания стандартов кода в проекте используется изолированный контейнер `audit`, который запускает цепочку проверок для всех 10 сервисов.

### Инструментарий:
-   **Ruff**: Мгновенный линтинг и проверка форматирования (заменяет Flake8, Isort, Black).
-   **Vulture**: Анализ статического дерева кода для поиска неиспользуемых функций, классов и переменных ("мертвый код").
-   **Deptry**: Проверка целостности зависимостей. Выявляет пакеты, которые указаны в `requirements.txt`, но не используются, или наоборот — используются в коде, но забыты в конфиге.

## 4. Наблюдаемость (Observability)

Инфраструктура подготовлена к интеграции полной системы мониторинга:
-   **Логирование**: Все сервисы пишут логи в стандартный поток (stdout/stderr) в формате JSON для удобного сбора через **Loki** или **ELK**.
-   **Метрики**: Реализованы Healthcheck-эндпоинты, которые позволяют оркестратору (Docker Compose / K8s) отслеживать состояние каждого компонента.
