# Архитектурные паттерны

Для обеспечения чистоты кода и разделения ответственности (Separation of Concerns) проект следует строгому набору архитектурных паттернов.

## 1. Domain-Driven Design (DDD) & Layered Architecture

Каждый микросервис разделен на слои, что позволяет изолировать бизнес-логику от деталей реализации (БД, API, внешние клиенты).

-   **API Layer**: Только роутеры и валидация схем.
-   **Service Layer**: "Чистая" бизнес-логика и оркестрация.
-   **Repository Layer**: Абстракция доступа к данным.
-   **Core Layer**: Инфраструктурный "клей" (UoW, конфиги).

## 2. Unit of Work (UoW)

Паттерн Unit of Work используется как единственный владелец сессии базы данных в рамках одного запроса.

**Преимущества для банка:**
-   **Атомарность**: Гарантирует, что либо все изменения в рамках бизнес-операции будут сохранены, либо ни одного.
-   **Управление событиями**: UoW накапливает доменные события (`Domain Events`) и публикует их в RabbitMQ **только после** успешного коммита в БД. Это решает проблему консистентности между БД и брокером сообщений.

## 3. Command Query Responsibility Segregation (CQRS)

Мы разделяем потоки изменения данных (Commands) и получения данных (Queries).

-   **Write Path**: Использует ORM (SQLAlchemy) и репозитории для обеспечения целостности данных.
-   **Read Path**: Может использовать "сырой" SQL для оптимизации сложных выборок, минуя оверхед ORM. Это особенно важно для построения финансовых отчетов и выписки по счету.

## 4. Event-Driven Architecture (EDA)

Межсервисное взаимодействие для побочных эффектов (логирование, уведомления) реализовано через асинхронные события.

**Ключевые аспекты:**
-   **Слабая связанность**: `Transaction Service` не знает о существовании `Notification Service`. Он просто публикует событие `TransactionCreated`.
-   **Масштабируемость**: Обработка тяжелых операций (отправка Email, сложная аналитика) вынесена из основного потока запроса, что ускоряет ответ пользователю.
-   **Надежность**: При временной недоступности потребителя (например, `Log Service`), сообщения будут безопасно храниться в очереди RabbitMQ до восстановления сервиса.
