# Движок AML (Anti-Money Laundering)

Сервис безопасности (`security_service`) реализует превентивный мониторинг транзакций на основе набора правил, соответствующих рекомендациям ФСМ РФ и международным стандартам банковской безопасности.

## 🛠️ Принципы работы

Каждая транзакция перед выполнением проходит через конвейер проверок. Если срабатывает хотя бы одно правило, создается объект **Violation** (Нарушение), и транзакция может быть автоматически заблокирована.

## 📋 Реализованные правила

### 1. Крупная разовая операция (`large_single_tx`)
- **Суть**: Выявление платежей, превышающих установленный порог (например, 600 000 ₽).
- **Логика**: Прямое сравнение суммы текущей операции с системным лимитом.

### 2. Суточный лимит по сумме (`daily_amount_limit`)
- **Суть**: Контроль суммарного объема операций пользователя за последние 24 часа.
- **Логика**: Система суммирует все успешные транзакции за сутки и прибавляет сумму текущей (pending) операции.

### 3. Суточный лимит по количеству (`daily_count_limit`)
- **Суть**: Ограничение частоты операций для предотвращения автоматизированного вывода средств.
- **Логика**: Подсчет количества успешных транзакций за 24 часа.

### 4. Серийные операции (Rapid-Fire)
- **Суть**: Выявление аномально частых операций за очень короткий промежуток времени (например, более 5 транзакций за 10 минут).
- **Логика**: Анализ временных меток последних операций пользователя.

### 5. Дробление транзакций (Structuring)
- **Суть**: Выявление попыток обойти контроль крупных сделок путем разбиения одной большой суммы на несколько мелких (чуть ниже порога).
- **Логика**: Алгоритм отслеживает серию операций, попадающих в диапазон `[threshold * 0.8, threshold)`.

### 6. Круглые суммы (Round Amount Pattern)
- **Суть**: Типичный признак транзитных операций или обналичивания — перевод крупных сумм без дробных частей (например, ровно 100 000, 500 000).
- **Логика**: Проверка кратности суммы установленному шагу (например, 10 000) при достижении минимального порога.

## 📈 Сбор данных и Аналитика

Для эффективной работы правил система использует:
- **Redis**: Для быстрой проверки частотных ограничений (Rate limiting).
- **Postgres Core**: Для получения истории операций в рамках транзакционной проверки.
- **MongoDB**: Хранилище всех зафиксированных нарушений (Violations) для последующего разбора инспекторами.
